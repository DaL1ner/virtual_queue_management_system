# Архитектура системы

## Описание системы

Сама идея разработки системы появилась, когда особенно острыми стали проблемы, связанные с физическим ожиданием в очередях для сдачи учебных практических и курсовых работ.  
  
Студенты тратят время на ожидание в физических очередях, вручную отслеживая изменения потока, что зачастую приводят к разногласиям и нерациональному времяпровождению. Преподаватели при этом не имеют инструментов для прогнозирования и управления этим потоком, что, как правило, усложняет процесс, если объём проверки учебных работ большой.  
  
При более детальном рассмотрении данной проблемы выяснилось, что подобная ситуация возникает и в других местах, где отсутствует должный уровень автоматизации процесса управления очередью.  
  
В связи с этим команда разработки данного проекта поставила себе цель разработать систему для управления виртуальной очередью, обеспечивающую удобную запись, отслеживание статуса и оптимизацию фактического потока клиентов.  
  
## Роли пользователей системы

Исходя из постановки задачи выделяются главные пользователи системы, чьи интересы необходимо учесть при разработке требований к системе:

- **Клиент очереди** - основной потребитель услуги. Может отслеживать состояние талона, выходить из очереди и уступать место.
- **Исполнитель услуги** - сотрудник, который принимает вызванного клиента, оказывает услугу и отслеживает состояние собственного обслуживания.
  
Кроме того, можно выделить и друге типы пользователей, которые так же будут осуществлять работу с системой:

- **Оператор** - Сотрудник, который вручную управляет потоком очереди: вызывает, перемещает или удаляет клиента из очереди без оказания услуги, осуществляет глубокий мониторинг очереди.
- **Администратор** - сотрудник системы, который управляет жизненным циклом очереди, настраивает конфигурации и типы обслуживания, назначает роли сотрудникам и просматривает историю событий.
- **Неавторизованный клиент** - пользователь, который ещё не вошёл в активную клиентскую сессию, но может начать постановку в очередь.
- **Наблюдатель очереди** - участник системы с доступом к общему мониторингу очереди, не имеющий места в очереди и прав на управление ею.

**ВАЖНО:** В MVP системы реализованы 2 роли: клиент и комбинированная роль исполнитель+оператор
