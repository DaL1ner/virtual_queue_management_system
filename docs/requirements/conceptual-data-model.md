## Обзор модели

Данная концептуальная модель данных разработана для системы управления виртуальной очередью (Virtual Queue Management System).

---

## Сущности

### User (Пользователь системы)

Хранит учётные данные сотрудников системы (Администраторы, Операторы, Исполнители). Клиенты очереди не создаются в этой таблице, так как системой реализуется анонимный доступ по ФИО.

| Русское название | Название (лат.) | Тип данных | Описание |
|------------------|-----------------|------------|----------|
| Идентификатор | id | Целочисленный (PK) | Уникальный идентификатор пользователя |
| Логин | login | Текстовый | Уникальный логин для входа в систему |
| Хеш пароля | password_hash | Текстовый | Хешированный пароль (bcrypt/argon2) |
| ФИО | full_name | Текстовый | Полное имя сотрудника |
| Email | email | Текстовый | Контактный адрес электронной почты |
| Активен | is_active | Логический | Флаг активности учётной записи |
| Дата создания | created_at | Дата и время | Дата создания учётной записи |
| Дата обновления | updated_at | Дата и время | Дата последнего обновления |

---

### Role (Роль)

Справочник системных ролей. Определяет права доступа к функциям системы.

| Русское название | Название (лат.) | Тип данных | Описание |
|------------------|-----------------|------------|----------|
| Идентификатор | id | Целочисленный (PK) | Уникальный идентификатор роли |
| Название | name | Текстовый | Отображаемое название роли (напр. "Оператор") |
| Код | code | Текстовый | Системный код для проверки прав (напр. "OPERATOR") |
| Описание | description | Текстовый | Описание полномочий роли |
| Дата создания | created_at | Дата и время | Дата создания роли |

---

### UserRole (Связь Пользователь-Роль)

Устраняет связь «Многие-ко-Многим» между пользователями и ролями. Один пользователь может иметь несколько ролей одновременно.

| Русское название | Название (лат.) | Тип данных | Описание |
|------------------|-----------------|------------|----------|
| Идентификатор | id | Целочисленный (PK) | Уникальный идентификатор записи |
| Пользователь | user_id | Ссылка на User | Ссылка на пользователя |
| Роль | role_id | Ссылка на Role | Ссылка на роль |
| Дата назначения | assigned_at | Дата и время | Дата назначения роли пользователю |
| Назначил | assigned_by | Ссылка на User | Кто назначил роль (Администратор) |

---

### Queue (Очередь - Конфигурация)

Шаблон очереди. Содержит настройки и правила, которые не меняются в течение сессии. Создаётся Администратором.

| Русское название | Название (лат.) | Тип данных | Описание |
|------------------|-----------------|------------|----------|
| Идентификатор | id | Целочисленный (PK) | Уникальный идентификатор очереди |
| Название | name | Текстовый | Отображаемое название очереди |
| Описание | description | Текстовый | Подробное описание очереди |
| Режим распределения клиентов | distribution_mode | Перечисление | MANUAL (ручной) или AUTO (автоматический) |
| Приоритеты включены | is_priority_enabled | Логический | Разрешено ли приоритетное обслуживание |
| Плановое среднее время обслуживания | avg_service_time_plan | Целочисленный | Плановое среднее время обслуживания в минутах |
| Активна | is_active | Логический | Флаг активности конфигурации |
| Дата создания | created_at | Дата и время | Дата создания конфигурации |
| Создал | created_by | Ссылка на User | Администратор, создавший очередь |

---

### QueueSession (Сессия очереди)

Конкретный запуск очереди во времени. Позволяет хранить историю работы за разные дни/периоды.

| Русское название | Название (лат.) | Тип данных | Описание |
|------------------|-----------------|------------|----------|
| Идентификатор | id | Целочисленный (PK) | Уникальный идентификатор сессии |
| Очередь | queue_id | Ссылка на Queue | Ссылка на конфигурацию очереди |
| Статус | status | Перечисление | DRAFT, OPEN, PAUSED, CLOSED |
| Время начала | started_at | Дата и время | Фактическое время начала работы сессии |
| Время завершения | closed_at | Дата и время | Время завершения сессии |
| Текущий номер талона | current_ticket_number | Целочисленный | Счётчик для генерации номеров талонов |
| Число обслуженных клиентов | served_count | Целочисленный | Счётчик обслуженных клиентов |
| Фактическое среднее время обслуживания | avg_service_time_actual | Целочисленный | Расчитывается автоматически |
| Общее время обслуживания | total_service_time | Целочисленный | Сумма времени всех обслуживаний. Расчитывается автоматически |
| Создал | created_by | Ссылка на User | Администратор, запустивший сессию |
| Дата создания | created_at | Дата и время | Дата создания сессии |

---

### Ticket (Талон / Запись в очередь)

**Ключевая сущность системы.** Представляет клиента в очереди. Содержит всю информацию о процессе обслуживания.

| Русское название | Название (лат.) | Тип данных | Описание |
|------------------|-----------------|------------|----------|
| Идентификатор | id | Целочисленный (PK) | Уникальный идентификатор талона |
| Сессия | session_id | Ссылка на QueueSession | Ссылка на активную сессию очереди |
| Номер талона | ticket_number | Текстовый | Видимый номер (напр. "А-005") |
| Имя клиента | client_name | Текстовый | Имя клиента (для анонимного входа) |
| Фамилия клиента | client_surname | Текстовый | Фамилия клиента |
| Уровень приоритета | priority_level | Целочисленный | 0 - обычный, 1+ - приоритетный |
| Порядок сортировки | sort_order | Числовой (DECIMAL) | Позиция для сортировки в очереди |
| Статус | status | Перечисление | WAITING, CALLED, SERVING, SERVED, SKIPPED, CANCELLED |
| Версия | version | Целочисленный | Для оптимистичной блокировки (конкурентность) |
| Время создания | created_at | Дата и время | Время записи в очередь (не меняется) |
| Время вызова | called_at | Дата и время | Когда клиент был вызван |
| Начало обслуживания | service_started_at | Дата и время | Когда началось обслуживание |
| Завершение обслуживания | service_ended_at | Дата и время | Когда завершилось обслуживание |
| Обслуживающий | served_by_user_id | Ссылка на User | Исполнитель, который обслуживал |
| Сессия клиента | client_session_id | Ссылка на ClientSession | Сессия устройства клиента |
| Причина отмены | cancel_reason | Текстовый | Причина отмены/пропуска (если есть) |

---

### ExecutorState (Состояние исполнителя)

Хранит состояние готовности исполнителя в рамках конкретной сессии очереди. Позволяет одному пользователю работать в нескольких очередях с разным статусом.

| Русское название | Название (лат.) | Тип данных | Описание |
|------------------|-----------------|------------|----------|
| Идентификатор | id | Целочисленный (PK) | Уникальный идентификатор записи |
| Сессия | session_id | Ссылка на QueueSession | Ссылка на сессию очереди |
| Пользователь | user_id | Ссылка на User | Исполнитель услуги |
| Готов | is_ready | Логический | Флаг готовности принимать клиентов |
| Текущий талон | current_ticket_id | Ссылка на Ticket | Талон, который сейчас обслуживается |
| Последнее изменение | last_status_change | Дата и время | Время последнего изменения состояния |
| Обслужено за сессию | served_count | Целочисленный | Счётчик обслуженных клиентов за сессию |

---

### ClientSession (Сессия клиента)

Отслеживает сессию браузера/устройства клиента. Нужно для реализации требования «один активный талон с устройства».

| Русское название | Название (лат.) | Тип данных | Описание |
|------------------|-----------------|------------|----------|
| Идентификатор | id | Целочисленный (PK) | Уникальный идентификатор сессии |
| Отпечаток устройства | device_fingerprint | Текстовый | Идентификатор устройства/браузера |
| Создана | created_at | Дата и время | Время создания сессии |
| Истекает | expires_at | Дата и время | Время истечения сессии |
| Активна | is_active | Логический | Флаг активности сессии |
| IP адрес | ip_address | Текстовый | IP-адрес клиента (для аудита) |
| User Agent | user_agent | Текстовый | Информация о браузере/устройстве |

| Русское название | Название (лат.) | Тип данных | Описание |
|------------------|-----------------|------------|----------|
| Идентификатор | id | Целочисленный (PK) | Уникальный идентификатор события |

| Талон | ticket_id | Ссылка на Ticket | Связанный талон (если есть) |
| Актор | actor_user_id | Ссылка на User | Кто совершил действие (или SYSTEM) |
| Тип события | event_type | Перечисление | TICKET_CREATED, CALLED, SERVICE_START, MOVE, и т.д. |
| Время события | timestamp | Дата и время | Дата и время события |
| Детали | details | Текстовый (JSON) | Дополнительные данные события |

## Связи между сущностями

```
┌─────────────┐       ┌─────────────┐       ┌─────────────┐
│    User     │───────│  UserRole   │───────│    Role     │
└─────────────┘   1:N └─────────────┘   N:1 └─────────────┘
       │
       │ (actor_user_id)
       ▼
┌─────────────┐       ┌─────────────┐       ┌─────────────┐
│  EventLog   │<──────│QueueSession │<──────│    Queue    │
└─────────────┘   N:1 └─────────────┘   N:1 └─────────────┘
       ▲                │
       │                │ (1:N)
       │                ▼
       │         ┌─────────────┐
       │         │   Ticket    │───────┐
       │         └─────────────┘       │
       │                │              │ (client_session_id)
       │                │ (served_by)  ▼
       │                ▼         ┌─────────────┐
       │         ┌─────────────┐  │ClientSession│
       │         │ExecutorState│  └─────────────┘
       │         └─────────────┘
       │                │
       │                │ (current_ticket_id)
       │                ▼
       │         ┌─────────────┐
       └────────>│  Ticket     │ (обратная связь)
                 └─────────────┘

┌─────────────┐       ┌─────────────┐
│   Ticket    │───────│Notification │
└─────────────┘   1:N └─────────────┘
```

## Бизнес-правила и ограничения

### 1. Управление позицией в очереди (sort_order)

```
Правило: sort_order использует десятичные числа с шагом 1000
Цель: O(1) перемещение без пересчёта всех записей

Пример:
  Талон 1: sort_order = 1000.0000000000
  Талон 2: sort_order = 2000.0000000000
  Талон 3: sort_order = 3000.0000000000

  При перемещении Талона 3 между 1 и 2:
  Талон 3: sort_order = 1500.0000000000
```

**Ренормализация:** Выполняется когда минимальный интервал < 100  
**Частота:** В фоновом режиме, когда очередь на паузе

---

### 2. Статусы талона (Lifecycle)

```
┌──────────┐    вызов    ┌──────────┐   начало    ┌───────────┐
│ WAITING  │ ──────────> │ CALLED   │ ──────────> │ SERVING   │
└──────────┘             └──────────┘             └───────────┘
     │                        │                        │
     │ отмена                 │ пропуск                │ завершение
     ▼                        ▼                        ▼
┌──────────┐             ┌──────────┐             ┌───────────┐
│CANCELLED │             │ SKIPPED  │             │ SERVED    │
└──────────┘             └──────────┘             └───────────┘
```

**Ограничения:**
- Переход из `SERVING` возможен только в `SERVED` или `SKIPPED`
- Переход из `CALLED` возможен в `SERVING`, `SKIPPED` или `WAITING` (возврат)
- Переход из `WAITING` возможен в `CALLED` или `CANCELLED`

---

### 3. Конкурентный доступ (Optimistic Locking)

| Поле | Назначение |
|------|------------|
| `Ticket.version` | Увеличивается при каждом обновлении |
| Проверка | `UPDATE Ticket SET version = version + 1 WHERE id = ? AND version = ?` |
| При конфликте | Вернуть ошибку 409 Conflict, запросить обновление данных |

---

### 4. Ограничения по сессии клиента

```
Правило: Один активный талон на одну ClientSession
Реализация: При создании нового талона:
  1. Найти все активные талоны с этим client_session_id
  2. Перевести их в статус CANCELLED
  3. Создать новый талон
```

---

### 5. Безопасность данных

| Требование | Реализация |
|------------|------------|
| Пароли | Хеширование bcrypt/argon2 (NFR-S-01) |
| Передача | HTTPS обязательно (NFR-S-02) |
| SQL Injection | Параметризированные запросы (NFR-S-03) |
| XSS | Санитизация всех входных данных (NFR-S-03) |
| Персональные данные | Не отображать Наблюдателю (3.7.2) |

---

### 6. Производительность

| Операция | Требование | Решение |
|----------|------------|---------|
| Обновление очереди | ≤ 3 сек (NFR-P-01) | WebSocket/SSE для real-time |
| Загрузка страниц | ≤ 2 сек (NFR-P-02) | Индексы на sort_order, status |
| Параллельные операторы | Без конфликтов (NFR-SC-01) | Optimistic locking + транзакции |

## 📎 Приложения

### A. Перечисляемые типы (Enums)

**Ticket.status:**
- `WAITING` — Ожидает вызова
- `CALLED` — Вызван, ожидает подтверждения
- `SERVING` — Обслуживается
- `SERVED` — Обслужен успешно
- `SKIPPED` — Пропущен (не явился)
- `CANCELLED` — Отменён клиентом или оператором

**QueueSession.status:**
- `DRAFT` — Черновик, не активна
- `OPEN` — Активна, принимает клиентов
- `PAUSED` — На паузе, не принимает новых
- `CLOSED` — Завершена

**Queue.distribution_mode:**
- `MANUAL` — Оператор вызывает клиентов вручную
- `AUTO` — Система автоматически назначает готовым исполнителям

**Notification.channel:**
- `WEB_PUSH` — Push-уведомление в браузере
- `SMS` — SMS-сообщение
- `EMAIL` — Электронная почта

---

### B. Минимальный набор данных для MVP

Для запуска MVP можно исключить:

| Сущность | Статус для MVP | Комментарий |
|----------|----------------|-------------|
| Notification | ⚠️ Упрощённо | Только WEB_PUSH, без SMS/EMAIL |
| EventLog | ✅ Обязательно | Критично для аудита |
| ClientSession | ✅ Обязательно | Нужно для контроля сессий |
| UserRole | ⚠️ Упрощённо | Можно поле role в User |

### C. Рекомендуемые индексы PostgreSQL

```sql
-- Ticket: основной запрос отображения очереди
CREATE INDEX idx_ticket_queue_sort ON Ticket(session_id, status, sort_order);

-- Ticket: поиск по сессии клиента
CREATE INDEX idx_ticket_client_session ON Ticket(client_session_id, status);

-- ExecutorState: поиск готовых исполнителей
CREATE INDEX idx_executor_ready ON ExecutorState(session_id, is_ready) WHERE is_ready = true;

-- EventLog: фильтрация по сессии и времени
CREATE INDEX idx_eventlog_session_time ON EventLog(session_id, timestamp);

-- ClientSession: поиск по отпечатку устройства
CREATE INDEX idx_clientsession_fingerprint ON ClientSession(device_fingerprint, is_active);
```
