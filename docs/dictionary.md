## 1. Роли и участники

| Термин | Определение |
|---|---|
| **Администратор** | Роль, отвечающая за настройку очереди, управление жизненным циклом очереди, административный мониторинг и работу с данными об операторах и исполнителях. |
| **Исполнитель услуги** | Роль сотрудника, который принимает вызванного клиента, подтверждает готовность к оказанию услуги, оказывает услугу и фиксирует завершение обслуживания. |
| **Клиент очереди** | Пользователь, уже поставленный в очередь. Может отслеживать состояние собственного талона, получать уведомления, выходить из очереди и, в предусмотренных сценариях, перемещаться к концу очереди на N шагов. |
| **Наблюдатель очереди** | Роль с доступом только к просмотру общего состояния очереди без участия в обслуживании и без управления очередью. |
| **Неавторизованный клиент** | Новый клиент, который ещё не вошёл в активную клиентскую сессию, но может начать сценарий постановки в очередь. |
| **Оператор** | Роль, управляющая текущим потоком очереди: вызывает клиента, перемещает его в очереди, удаляет клиента без оказания услуги и отслеживает состояние очереди. |
| **Оператор + Исполнитель** | Комбинированная роль, объединяющая полномочия оператора и исполнителя услуги. |
| **Пользователь** | Обобщающий участник системы на верхнем уровне модели, от которого специализируются конкретные роли проекта. |
| **Система** | Системный участник, инициирующий автоматические действия, например уведомления клиенту и автоматическое управление потоком очереди. |

## 2. Бизнес-процессы и сценарии

| Термин | Определение |
|---|---|
| **Административный мониторинг очереди** | Сценарий наблюдения за очередью с расширенным набором данных для оператора и администратора: список вызовов, текущая очередь, число клиентов, состояние исполнителей и агрегированные показатели обслуживания. |
| **Автоматический вызов первого клиента в очереди** | Сценарий, при котором система автоматически связывает первого клиента в очереди со свободным исполнителем, когда исполнитель готов к обслуживанию. |
| **Автоматическое управление потоком очереди** | Контур управления, в котором часть решений о назначении клиента исполнителю инициируется системой автоматически. |
| **Выход из очереди** | Сценарий добровольного отказа клиента от дальнейшего ожидания с переводом талона в отменённое состояние и завершением клиентской сессии. |
| **Вызов клиента в очереди** | Сценарий назначения клиента исполнителю и перевода талона в состояние «вызван». Может выполняться вручную оператором или в автоматическом режиме системой. |
| **Мониторинг обслуживания** | Сценарий наблюдения исполнителем за ходом текущего обслуживания и связанными с ним состояниями. |
| **Мониторинг состояния собственного талона** | Сценарий клиента по просмотру номера талона, текущей позиции, количества людей впереди, времени ожидания и назначенного исполнителя. |
| **Настройка очереди** | Административный сценарий изменения параметров и конфигурации очереди. |
| **Общий мониторинг очереди** | Сценарий просмотра текущего состояния очереди без управления клиентами: список вызовов, число клиентов, средние показатели обслуживания и состояния исполнителей. |
| **Оказание услуги** | Бизнес-процесс работы исполнителя с вызванным клиентом: подтверждение начала обслуживания, непосредственное обслуживание, фиксация завершения или отсутствия клиента. |
| **Перемещение клиента в очереди** | Сценарий изменения позиции клиента внутри очереди оператором или в разрешённых случаях через прикладные механизмы проекта. |
| **Перемещение к концу очереди на N шагов** | Специализированный сценарий клиента, в котором его талон сдвигается назад на указанное число шагов. |
| **Постановка в очередь** | Начальный сценарий клиента: ввод имени и фамилии, выбор типа обслуживания, создание клиентской сессии, инициализация талона и первичный расчёт порядка в очереди. |
| **Получение уведомлений о действиях с талоном** | Сценарий клиента по получению уведомлений при изменении состояния талона или связанных с ним действий системы. |
| **Ручной вызов** | Подсценарий управления очередью, при котором оператор вручную выбирает клиента и свободного исполнителя для назначения. |
| **Ручное управление потоком очереди** | Контур управления, в котором ключевые действия по вызову, перемещению и удалению клиентов инициируются оператором или администратором. |
| **Системная авторизация** | Сценарий входа сотрудников в систему по логину и паролю с созданием сессии системной роли. |
| **Смена готовности к оказанию услуги** | Сценарий подтверждения или отмены готовности исполнителя принять следующего клиента. |
| **Удаление клиента из очереди без оказания услуги** | Сценарий принудительного исключения клиента из очереди оператором или администратором без перевода в состояние «обслужен». |
| **Уведомление клиента о действиях с его талоном** | Сквозной сценарий получения информации об изменениях талона, вычисления объекта изменений и отправки уведомления клиенту. |
| **Управление жизненным циклом очереди** | Административный сценарий управления состояниями сессии очереди на протяжении её существования. |

## 3. Сущности и хранимые данные

| Термин | Определение |
|---|---|
| **Архив талонов** | Хранилище завершённых или выведенных из активной работы талонов. |
| **Данные вызовов** | Набор данных, используемых в сценариях вызова клиента, мониторинга очереди и обслуживания. |
| **Данные о событиях с талонами** | История изменений и действий, связанных с конкретными талонами. |
| **Данные об операторах и исполнителях** | Справочные и операционные данные, необходимые для настройки очереди и назначения ролей исполнения. |
| **Журнал вызовов** | Хранилище записей о фактах вызова клиентов и связанных действиях. |
| **Журнал событий с талонами** | Хранилище событий, фиксирующее изменения в жизненном цикле талонов. |
| **Имя и фамилия** | Набор данных, вводимый клиентом при постановке в очередь. |
| **Конфигурация очереди** | Прикладной набор параметров очереди, которым управляет администратор в сценарии настройки очереди. В словарике v1 соответствует сущности **QueueConfig**. |
| **Конфигурация системы** | Хранимые системные настройки технологического уровня, используемые сервером БД и прикладными сервисами. |
| **Логин и пароль** | Данные для системной авторизации сотрудников. |
| **Новая позиция** | Значение, задающее целевое место клиента при перемещении в очереди. |
| **Номер талона** | Видимый пользователю идентификатор его записи в очереди. |
| **Очередь** | Основная предметная сущность, содержащая активный поток клиентов, правила сортировки и текущее состояние обслуживания. |
| **Пользователь системы (User)** | Учётная запись сотрудника системы. В словарике v1 этим термином обозначается системный пользователь с одной или несколькими ролями. |
| **Роль (Role)** | Справочная сущность, определяющая права и область ответственности системного пользователя. |
| **Связь пользователь–роль (UserRole)** | Связующая сущность, позволяющая одному системному пользователю иметь несколько ролей. |
| **Сессии пользователей** | Обобщённое хранилище активных пользовательских сессий в прикладном слое. |
| **Сессия клиента (ClientSession)** | Сущность, отражающая активное взаимодействие клиента с системой в пределах одного сценария ожидания и получения услуги. |
| **Сессия очереди (QueueSession)** | Конкретный жизненный цикл запущенной очереди во времени. |
| **Сессия системной роли** | Активная сессия сотрудника после успешной авторизации. |
| **Состояние исполнителя (ExecutorState)** | Сущность, отражающая готовность исполнителя и его связь с текущим обслуживанием. |
| **Состояния исполнителей** | Совокупность текущих состояний всех исполнителей, используемая в мониторинге, вызовах и обслуживании. |
| **Список исполнителей** | Хранимый перечень исполнителей, доступный системе для назначения и настройки. |
| **Список операторов** | Хранимый перечень операторов, доступный системе для настройки и администрирования. |
| **Талон (Ticket)** | Ключевая сущность проекта, представляющая клиента в очереди и отражающая его путь от постановки в очередь до завершения обслуживания или выхода из очереди. |
| **Талоны** | Коллекция всех талонов, используемая в расчёте очереди, мониторинге, вызовах и хранении истории. |
| **Тип обслуживания (ServiceType)** | Категория обслуживания, выбираемая при постановке в очередь и влияющая на правила обработки талона. |
| **Уведомление** | Сообщение клиенту или исполнителю о значимом изменении состояния, назначения или действия с талоном. |
| **Число шагов** | Значение, определяющее величину сдвига клиента назад в очереди при сценарии перемещения на N шагов. |

## 4. Статусы, состояния и режимы

### 4.1. Статусы талона

| Термин | Определение |
|---|---|
| **Вызван (CALLED)** | Клиент назначен исполнителю и ожидает начала обслуживания или подтверждения факта своего присутствия. |
| **Обслужен (SERVED)** | Обслуживание клиента завершено успешно. |
| **Обслуживается (SERVING)** | Клиент находится в активной фазе обслуживания. |
| **Ожидает (WAITING)** | Исходное активное состояние талона после постановки в очередь и до вызова. |
| **Отменён (CANCELLED)** | Талон выведен из активной очереди без оказания услуги по инициативе клиента или в прикладном сценарии отмены. |
| **Пропущен (SKIPPED)** | Клиент был вызван, но обслуживание не состоялось из-за его отсутствия. |

### 4.2. Статусы сессии очереди

| Термин | Определение |
|---|---|
| **Закрыта (CLOSED)** | Сессия очереди завершена и больше не обслуживает новые действия как активная. |
| **Открыта (OPEN)** | Сессия очереди активна и используется для работы с клиентами. |
| **Приостановлена (PAUSED)** | Работа очереди временно остановлена без окончательного закрытия. |
| **Черновик (DRAFT)** | Подготовленное, но ещё не запущенное состояние сессии очереди. |

### 4.3. Состояния исполнителя

| Термин | Определение |
|---|---|
| **Готов** | Исполнитель доступен для назначения следующего клиента. |
| **Не готов** | Исполнитель временно недоступен для назначения нового клиента. |

### 4.4. Режимы управления

| Термин | Определение |
|---|---|
| **Автоматический режим (AUTO)** | Режим, в котором система может автоматически назначать клиента исполнителю при выполнении необходимых условий. |
| **Ручной режим (MANUAL)** | Режим, в котором вызов и ключевые действия управления очередью инициируются человеком. |

## 5. Мониторинг и показатели

| Термин | Определение |
|---|---|
| **Время ожидания клиента** | Показатель, отражающий, сколько времени клиент уже ждёт или предположительно будет ждать до начала обслуживания. |
| **Назначенный исполнитель** | Исполнитель, закреплённый за конкретным клиентом или талоном в момент вызова или обслуживания. |
| **Общее среднее время обслуживания** | Агрегированный показатель среднего времени обслуживания по очереди в целом. |
| **Общее число обслуженных клиентов** | Суммарное число клиентов, для которых обслуживание завершено успешно. |
| **Примерное время ожидания клиента** | Расчётная оценка оставшегося времени ожидания до обслуживания. |
| **Среднее время обслуживания** | Средний показатель времени обслуживания, используемый в мониторинге и оценке ожидания. |
| **Среднее время обслуживания исполнителя** | Средний показатель времени обслуживания по конкретному исполнителю. |
| **Список текущей очереди** | Представление активного состава очереди в текущий момент времени. |
| **Список текущих вызовов** | Представление клиентов, которые уже вызваны и ожидают начала обслуживания либо находятся в связанном состоянии вызова. |
| **Текущая позиция в очереди** | Место клиента в очереди на текущий момент. |
| **Число клиентов в очереди** | Количество клиентов, находящихся в активной очереди. |
| **Число людей впереди очереди** | Количество клиентов, стоящих перед конкретным талоном в очереди. |

## 6. Сервисы и внутренние подсистемы

| Термин | Определение |
|---|---|
| **Автоматический вызов** | Внутренняя подсистема, реализующая автоматический подбор первого клиента и свободного исполнителя. |
| **Ввод информации** | Внутренняя подсистема, обеспечивающая ввод имени и фамилии, выбор типа обслуживания и ввод данных для перемещения или удаления клиента. |
| **Расчёт метрик времени обслуживания** | Внутренняя подсистема, вычисляющая показатели ожидания и обслуживания по очереди и исполнителям. |
| **Расчёт очереди** | Внутренняя подсистема, отвечающая за формирование порядка очереди, проверку корректности новой позиции и пересчёт сортировки. |
| **Ручной вызов** | Внутренняя подсистема, связывающая клиента с выбранным исполнителем по инициативе оператора. |
| **Сервис ввода информации** | Прикладной сервис, предоставляющий интерфейс к операциям ввода данных для клиентских и операторских сценариев. |
| **Сервис доступа к данным** | Технологический сервис, обеспечивающий обращение прикладного слоя к серверу БД. |
| **Сервис доступа к веб-приложению** | Технологический сервис, обеспечивающий публикацию и доступность веб-приложения для пользователя. |
| **Сервис настройки очереди** | Прикладной сервис, предоставляющий интерфейс к конфигурации и параметрам очереди. |
| **Сервис оказания услуги** | Прикладной сервис, связывающий исполнительские сценарии начала, ведения и завершения обслуживания. |
| **Сервис расчёта метрик времени обслуживания** | Прикладной сервис, через который верхний уровень получает показатели ожидания и обслуживания. |
| **Сервис расчёта очереди** | Прикладной сервис, предоставляющий операции определения позиции клиента и пересчёта очереди. |
| **Сервис уведомления клиента** | Прикладной сервис отправки уведомлений клиенту об изменениях его талона. |
| **Сервис уведомления исполнителя** | Прикладной сервис уведомления исполнителя о назначении клиента и связанных с этим событиях. |
| **Сервис управления вызовами** | Прикладной сервис, обеспечивающий вызов клиента, связывание с исполнителем и сопровождение вызовов. |
| **Сервис управления сессиями** | Прикладной сервис, обеспечивающий создание, проверку и завершение клиентских и системных сессий. |
| **Сервис управления талонами** | Прикладной сервис, управляющий состояниями талонов, приоритетом и порядком сортировки. |
| **Сервис хранения данных** | Технологический сервис, отвечающий за физическое хранение данных очереди и связанных журналов. |
| **Уведомление клиента** | Внутренняя подсистема, формирующая и отправляющая клиентские уведомления. |
| **Уведомление исполнителя** | Внутренняя подсистема, отправляющая исполнителю сведения о назначенном клиенте. |
| **Управление вызовами** | Внутренняя подсистема, работающая с текущими вызовами, назначениями и состояниями исполнителей. |

## 9. Ключевые проектные и технические понятия

| Термин | Определение |
|---|---|
| **409 Conflict** | Код ошибки, используемый для обозначения конфликта конкурентного изменения записи. |
| **Audit Trail** | Непрерывная история действий в системе, фиксируемая через журналы и события. |
| **device_fingerprint** | Идентификатор устройства или браузера, используемый для привязки клиентской сессии и контроля повторных постановок в очередь. |
| **O(1) перемещение** | Подход к перемещению клиента в очереди без полного пересчёта всех позиций. |
| **Polling** | Периодическое обновление данных клиентского интерфейса запросами к серверу для получения актуального состояния очереди. |
| **priority_level** | Уровень приоритета талона, влияющий на его положение в очереди и правила обработки. |
| **QR-код** | Код для быстрого входа клиента в сценарий постановки в очередь с мобильного устройства. |
| **sort_order** | Значение порядка сортировки талона внутри очереди, используемое при расчёте позиции и перемещении клиента. |
| **Эскалация приоритета** | Механизм повышения приоритета клиента после слишком долгого ожидания. |
| **Жизненный цикл талона** | Полная последовательность состояний талона: от создания и ожидания до вызова, обслуживания, пропуска или отмены. |
| **Оптимистичная блокировка (Optimistic Locking)** | Механизм защиты от конфликтов параллельного обновления одной и той же записи. |
| **Ренормализация sort_order** | Пересчёт значений порядка сортировки талонов, когда промежутки между соседними значениями становятся недостаточными для дальнейших вставок и перемещений. |

## 10. Нефункциональные требования (NFR)

| Термин | Определение |
|---|---|
| **Google Lighthouse** | Инструмент оценки производительности и качества веб-интерфейса. Используется для проверки качества клиентской части проекта. |
| **JMeter** | Инструмент нагрузочного тестирования, применяемый для проверки поведения системы при одновременной работе нескольких клиентов. |
| **NFR (Non-Functional Requirement)** | Нефункциональное требование, описывающее не бизнес-функцию, а ожидаемые качественные характеристики системы: производительность, безопасность, надёжность и удобство использования. |
| **Performance (Производительность)** | Требование к скорости отклика и обновления состояния очереди, а также к приемлемому времени загрузки веб-интерфейса. |
| **Reliability (Надёжность)** | Требование к устойчивой работе системы, сохранности данных и доступности сервиса в рабочее время. |
| **Scalability (Масштабируемость)** | Требование к способности системы работать с несколькими операторами, исполнителями и одновременными клиентскими сессиями без критических конфликтов. |
| **Security (Безопасность)** | Требование к защите пользовательских данных, безопасной авторизации, передаче данных по защищённому каналу и защите от типовых веб-угроз. |
| **Usability (Удобство)** | Требование к понятности и простоте интерфейса: клиент должен быстро встать в очередь, а сотрудник — выполнять основные операции за минимальное число действий. |

## 11. Архитектурные стили

| Термин | Определение |
|---|---|
| **ADR (Architecture Decision Record)** | Документ, фиксирующий принятое архитектурное решение, его контекст, альтернативы и последствия для проекта. |
| **MVP (Minimum Viable Product)** | Минимально жизнеспособная версия продукта, достаточная для проверки ценности решения и демонстрации ключевых сценариев виртуальной очереди. |
| **Single Responsibility** | Принцип, по которому каждый компонент или подсистема должны иметь одну основную ответственность. |
| **Super-thin client** | Подход, при котором клиентское приложение остаётся максимально лёгким и не переносит на себя ключевую бизнес-логику сервера. |
| **Единственный источник истины** | Принцип, при котором актуальное состояние системы хранится централизованно, а не дублируется в нескольких независимых местах. |
| **Трёхзвенная архитектура** | Базовая архитектурная схема вида «клиент — сервер приложения — база данных». |
| **Четырёхзвенная архитектура** | Расширенная архитектурная схема, в которой между клиентом и прикладным сервером выделяется дополнительное звено доступа, например веб-сервер или прокси. |
